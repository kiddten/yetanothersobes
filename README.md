# Технические разборы

Сайт на официальном шаблоне Quarto Blog. Используется Quarto 1.10.18.
Python, R и Node.js для текущих страниц не нужны.

## Локальный просмотр

Из корня проекта:

```sh
quarto preview
```

Сборка без запуска сервера:

```sh
quarto render
```

Готовый сайт находится в `_site/`. Служебные и собранные файлы не входят в исходники.

## Новый разбор

Создайте `posts/<slug>/index.qmd` по образцу `templates/post.qmd`.
Обновите название, описание, дату и категории; уберите `draft: true`,
когда материал готов к публикации. Изображения храните рядом со статьёй.
Каталог и поиск обновляются при сборке.

Структура: контекст → основная идея → механизм со схемой → пример →
ограничения → источники. Учтите исправления из чата, уберите повторы,
проверьте технические утверждения. Не публикуйте сырой чат по умолчанию.

Mermaid использует блоки с языком `{mermaid}`. Для демонстрации Python-кода
используйте `python`, без фигурных скобок, чтобы не запускать его при сборке.
Интерактивные элементы можно добавлять через HTML/JS или Observable JS.

## GitHub Pages (когда понадобится публикация)

1. Подключите проект к GitHub-репозиторию и отправьте исходники в `main`.
2. В Settings → Pages → Build and deployment выберите Source: GitHub Actions.
3. Workflow `.github/workflows/publish.yml` соберёт и опубликует сайт.
   Его также можно запустить вручную на вкладке Actions.
4. Дождитесь успешного завершения workflow; ссылка будет в deployment.

Workflow выполняет только сборку Quarto и публикацию статических файлов.
Он не устанавливает Python/R и не запускает вычислительные notebooks.
RSS пока выключен; перед включением укажите реальный `website.site-url`.

## Работа из чата

В конце технического обсуждения используйте [промпт для превращения чата в статью](prompts/chat-to-article.md).

«Собери разбор из этого чата» — создать/обновить статью и проверить локально.
«Собери и опубликуй» — дополнительно отправить изменения и дождаться деплоя,
если GitHub уже подключён. Публикация требует отдельного явного запроса.
